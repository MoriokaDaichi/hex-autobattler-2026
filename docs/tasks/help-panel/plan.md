intent.md(同フォルダ)の設計。実装担当はこのファイルとintent.mdだけで着手できるよう自己完結させる。

## 0. 方針

- 並行作業中のドラッグ&ドロップ(Game.cppの準備フェーズ入力まわり)とのマージ衝突を減らすため、
  ヘルプは新規ファイルに閉じ込め、Game.cpp/Game.hの変更は「生成・呼び出し・ヒット領域登録・入力ブロック」
  の数行に限定する。
- 説明文の数値はハードコードせず、可能な限りコード上の定数/データベースから`swprintf_s`で組み立てる
  (定数を変えればヘルプも自動で追従する)。

## 3. カテゴリ構成(7個)

1. 基本の流れ: 目的(全`GameState::kTotalRounds`ラウンド)、準備→戦闘→結果、同じ敵に`kMaxLossesPerEnemy`敗でゲームオーバー、相打ちは敗北扱い、敵プレビュー、F5セーブ。
2. 操作: マウス(クリック/右クリック2回/ドラッグ&ドロップは一般的な記述)、ゲームパッド(Back/十字/A/X/LB/Y/RB/Start/B)、ヘルプの開閉、パッド未接続時のキー割当。
3. 経済: 基本収入`kBaseIncome`、利子(`kGoldPerInterest`ごと+1・上限`kMaxInterest`)、連勝(`GetWinStreakBonus`で2〜5連勝の例を生成)、連敗表(`GetLossStreakBonus`から生成)、`kWinStreakItemMinStreak`連勝以上でアイテム+1、購入/リロール(`ShopSystem::kRerollCost`)/経験値購入(`LevelSystem::kBuyXPCost`/`kBuyXPAmount`)/売却額、ショップロック。
4. ユニットと星: ショップ5枠、3体合成(星1→2→3)、倍率`StarLevelSystem::kStarMultiplierStep`、盤面上限=レベル、自陣手前3行、経験値(毎ラウンド`kPassiveXPPerRound`)、必要経験値表(`LevelSystem::XPForNextLevel`)、レベル別出現率表(`ShopSystem::GetCostOdds`)。合成・売却で装備が消える注意。
5. 戦闘: 自動戦闘、最寄りの敵をねらい射程外なら移動、攻撃速度、必殺技ゲージ(通常攻撃+被弾で+1、必要数到達で必殺技→0)、必殺技4種、シールド、物理(攻撃力/物理防御)と魔法(魔力/魔法防御)、軽減式100/(100+防御)・最低1、火傷、戦闘前HP全回復・トレイトは開始時固定。
6. アイテム: 勝利で素材1つ(+連勝ボーナス)、装備方法、上限`ItemSystem::kMaxItemSlots`、素材2つで自動合成(枠が満杯でも合成可)、外せない、素材一覧と全21レシピ(`ItemDatabase`から生成、効果も表示)。
7. トレイト: 発動のしくみ(盤面のみ数える、同じユニットも1体ずつ数える、最高段階のみ有効、該当ユニットだけに効果)、全トレイトの段階と効果(`TraitDatabase`から生成)。

効果表記はヘルプ独自に日本語で書く(`UITextUtil::EffectShortText`はマイナス値が`技+-1`になるため使わない):
攻撃力/魔力/最大HP/物理防御/魔法防御/攻撃速度/必殺技の必要ゲージ、%付きは「基礎値の%」。

## 4. ページ送りの方式

- 行データは`HelpContent`が論理行で返す(見出し行フラグ付き、空行可)。
- `HelpUIRenderer::Init`で各行を`UITextUtil::EstimateTextWidth`(scale0.5)で測り、本文幅を超える行は
  文字単位で折り返す(続き行は元の行頭インデント+全角1文字ぶん字下げ)。
- 1ページ最大20行で分割。見出しがページ末尾2行以内に来る場合は次ページへ送る。ページ先頭の空行は捨てる。
- カテゴリを切り替えるとページは0へ。開き直したときは前回のカテゴリ・ページを維持。

## 5. 入力

- 開閉: ヘルプボタン左クリック / F1 / Hキー / パッドLT(enButtonLB2。パッド未接続時のキーボード代替は'N')。
  閉じる: 閉じるボタン / Esc / パッドB(パッド未接続時は'K') / 開閉キー。
- 開いている間: 十字キー上下(またはキーボード↑↓)でカテゴリ、左右でページ。タブ/前へ/次へをクリック。
  パネル外クリックは何もしない(閉じない)。

### 入力のブロック方法

1. **マウス**: `Game::Update()`でヒット領域を組み立てた最後(=`m_uiInteraction.Update()`直前)に
   `m_helpUI.BuildHotRegions(m_hotRegions)`を呼ぶ。開いている間はリストを**clearしてから**
   全画面の`HelpBlocker`+パネル内のボタン類だけを登録するので、盤面・ショップ等はクリックもホバーも
   解決されない(ツールチップも出ない。`TooltipContentBuilder::Build`はヘルプ種別に対し空を返す)。
   閉じている間はヘルプボタンを末尾に追加するだけ(後ろから探索されるので最優先でヒット)。
2. **パッド/キーボード**: `m_uiInteraction.Update()`の直後に`m_helpUI.UpdateInput(m_uiInteraction)`を呼び、
   `helpBlocksInput = (開く前に開いていた || 今開いている) && フェーズがTitle/Preparation/GameOver/Victory`
   を求める。既存のフェーズ分岐チェーンの先頭に`if (helpBlocksInput) { }`を1つ足すだけで、その
   フレームのタイトル/準備/終了画面の入力処理を丸ごとスキップする(フェーズ遷移も起きない)。
   「閉じる前の状態」も見るのは、Bで閉じたフレームに同じBで戦闘開始してしまうのを防ぐため。
   Combat/Resultは対象外(戦闘の進行は止めない。intent要求6)。
3. `m_cursorSelection.Update()`もヘルプ表示中は呼ばない(十字キーがヘルプ操作と二重に効かないように)。

## 6. 描画順

`Game::Render()`の末尾(ツールチップより後)で`m_helpUI.Draw()`→AddRenderObject。2Dパスは登録順に
描かれるため、最前面になる。タイトル画面は`Render()`が早期returnするので、その分岐内でも呼ぶ。
矩形(UIRectRenderer)はFont::Begin()より前にまとめて描く(既存UIと同じ制約)。

## 7. フォント

`myfile.spritefont`の収録文字を実際に抽出して確認済み(21,572字、JIS第1・第2水準相当の漢字を収録)。
未収録で「?」になる記号: ★ ☆ × → ← ↑ ↓ … ① ◆ ● ■ ▲ など。→ 本文では使わず、矢印は`->`、
星は「星2」/`*2`(既存UIの表記)、倍は`x`、箇条書きは`・`(収録済み)を使う。
実装後に本文の全文字をフォントの収録表と突き合わせて未収録が無いことを確認する。

## 8. 未解決の懸念

- `kRerollCost`はGame.cppにローカル定数が2箇所残っている(`ShopSystem::kRerollCost`と同値の手書き)。
  D&Dマージ後に寄せる。
- 合成・売却で装備アイテムが消えるのは現仕様(TryMergeUnitsが新規UnitInstanceを作る)。ヘルプでは注意書きとして記載。
- ドラッグ&ドロップ側がマウス入力を`m_uiInteraction`経由でなく`g_mouse`直読みで扱う場合でも、準備フェーズの
  分岐自体をスキップするのでヘルプ表示中は動かない想定。ただしD&Dのコードが分岐の外に置かれた場合は要確認。
