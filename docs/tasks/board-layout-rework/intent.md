# board-layout-rework — 要件定義 (intent.md)

## 背景

ユーザーの F5 プレイで挙がったゲーム性・見た目の問題:

1. **ユニットモデルが大きすぎる**。ヘックス1マスに対してモデルが大きく、隣のユニットと見た目が重なる。
   マス自体のクリック（ui-mouse-cards の盤面ヒットテスト）もモデルに隠れてやりにくい。
   （モデルは現状おおよそ10倍スケールで描かれている。CLAUDE.md / `UnitModelDisplay` 参照。）
2. **盤面が狭く浅い**。現状は 1枚の共有盤面 `q:0-8 × r:0-2`（27ヘックス、pointy-top、`kHexSize=50`）で、
   `0-2:自陣 / 3-5:中立 / 6-8:敵陣` とゾーン分けしている
   （`HexGridRenderer::kAllyZoneMinQ/MaxQ = 0/2`、`Player::kAllyZoneMinQ/MaxQ = 0/2`）。
   実質プレイヤーが置けるのは 3列×3行=9マスしかない。
3. **タイトル/GameOver 画面に前プレイのユニットモデルの薄いシルエットが残る**
   （`UnitModelDisplay` がフェーズ遷移で盤面ユニットのモデルを消していない既存バグ。ui-mouse-cards の
   デバッグ検証でも確認済み）。

## 目的

ユーザー指定のとおり盤面を作り直す:

- **現在の 3×9（27マス）のグリッドを、まるごとプレイヤーの陣地にする**（プレイヤーは全27マスに配置可能）。
- **画面の上側に、同じ 3×9（27マス）のグリッドをもう1枚、敵の陣地として新設する**。
- あわせて**ユニットモデルを縮小**し、1体が概ね1マスに収まり隣と重ならないようにする（マスのクリックも
  しやすくする）。
- **タイトル/GameOver のゴーストユニット表示を修正**する（フェーズ遷移でモデルを片付ける）。

## スコープ（In）

### A. 盤面の 2 ゾーン化

- プレイヤー盤面: 3行×9列 = 27マス。画面手前（カメラ寄り）。プレイヤーはこの全マスに配置/再配置できる。
- 敵盤面: 3行×9列 = 27マス。画面奥（上側）。敵編成（`EnemyFactory` / `EnemyStage` テーブル）はここに配置される。
- 2盤面の間隔・見た目上の分離（中立ゾーンは廃止 or 細い境界に置き換え。設計フェーズで決定）。
- ヘックス座標系の扱い（1つの座標空間を r 方向に拡張するのか、`HexCoord` に盤面サイド情報を足すのか、
  盤面ごとに別座標にするのか）は **plan.md で設計**する。既存の `HexCoord` / `HexCoord::ToWorldPosition` /
  `HexGridRenderer::CalcTileCenter` / `TryWorldPositionToHex` / `TryMouseToHex` への影響を洗い出すこと。
- カメラ（現状 `pos {0,900,-650}`, target 原点, 固定）を、両盤面（合計6行×9列相当）が画角に無理なく
  収まるよう再設定する。

### B. 戦闘時の 2 盤面の接続（★設計フェーズで要検討・未確定）

- `CombatEngine` は「最も近い敵へ向かう貪欲な隣接ヘックス移動」。2盤面が分離すると、プレイヤー盤面の
  ユニットが敵盤面のユニットへどう到達するかを定義する必要がある。
- 想定される最小案: 戦闘中は「プレイヤー3行 + 敵3行」を縦に連結した 6行×9列の1つの戦場として扱い、
  ユニットは通常どおり隣接移動する（TFT本家の「自陣と相手陣がミラー合体して1つの戦場になる」に相当）。
  この案でよいか、別の接続モデルにするかは plan.md で確定し、必要なら着手前にユーザー確認。
- `EnemyStage` テーブル（`Game::BuildEnemyStages`、手書きの敵配置。現状 q6-8 座標）は新しい敵盤面の
  座標へ移し替える。マスが増えるので配置の見直し余地はあるが、**数値バランスの再設計は本タスクのスコープ外**
  （座標の移し替えと、破綻しない範囲の微調整まで）。

### C. ユニットモデルの縮小

- `UnitModelDisplay` のスケール（現状の約10倍）を、1体が概ね1マス（`kHexSize=50` 基準）に収まる大きさへ
  縮小する。HPバー等の頭上表示の高さオフセット（`BoardUIRenderer` の `kBarWorldY` 等）も追随調整。
- ベンチのモデル表示（もしあれば）への影響も確認。

### D. タイトル/GameOver のゴースト修正

- `UnitModelDisplay`（または `Game` のフェーズ遷移処理）で、Title / GameOver / Victory へ入るときに
  盤面ユニットのモデル描画を確実に停止/非表示にする。準備フェーズへ戻ったら再表示。

### E. ui-mouse-cards（盤面ヒットテスト）の追随

- `feature/ui-mouse-cards` が先に main へマージされる前提。盤面のヒット領域構築
  （`Game::Update()` の `BuildHotRegions` 盤面ループ、`kHexHitHalfSize` 異方性ボックス）は、
  新しいプレイヤー盤面（27マス）と新カメラ/新スケールに合わせて更新・再調整する。
- 敵盤面はプレイヤーが配置できないのでヒット領域は不要だが、フェーズ2のツールチップで敵ユニットに
  ホバー情報を出したいなら `BoardUnit`（敵側）のヒット領域を足す判断は plan.md で。

## スコープ（Out）

- ユニット/トレイト/アイテム/経済の**数値バランス再設計** → 対象外。
- 3D戦闘の移動アニメ・エフェクト、モデルの差し替え → 対象外。
- 盤面の形状変更（六角形以外、行数を3から変える等、ユーザー指定の 3×9 以外）→ 対象外。
- カメラ操作（プレイヤーによる回転/ズーム）→ 対象外（固定カメラの再設定のみ）。
- UI/カード/ツールチップの見た目の作り込み → ui-mouse-cards 側の話。ここは E の追随のみ。

## 受け入れ条件

- 準備フェーズで、プレイヤー盤面の 3×9=27マスすべてにマウス（および既存操作）でユニットを配置/再配置できる。
- 画面上側に敵盤面 3×9 が表示され、`EnemyStage` の敵編成がそこに出る。
- 戦闘フェーズで、両盤面のユニットが交戦し、決着（勝敗判定）が従来どおり成立する
  （相打ち・全滅・撃破の判定が壊れていない）。
- ユニットモデルが概ね1マスに収まり、隣接ユニットと大きく重ならない。マスのクリックがモデルに
  ほぼ邪魔されない。
- タイトル / GameOver / Victory 画面に、前プレイのユニットモデル（シルエット含む）が残らない。
- 既存のゲームパッド操作・キーボード（F5等）が従来どおり動く。
- `Debug|x64` ビルドが 0 エラー。実機 F5 で各フェーズの表示が破綻していない。

## 制約・注意

- 盤面の「正」は現状 `HexGridRenderer`（`kAllyZoneMinQ/MaxQ`）と `Player`（同名定数を再掲）に二重に
  持たれている。2ゾーン化に合わせて、この定義の持ち方も整理する（片方をソースにする等）。
- `CombatEngine` / `CombatPlayback` / `BoardUIRenderer::WorldToUI` / `UnitModelDisplay` は
  `CalcTileCenter` のワールド座標に依存している。座標系・カメラを変えると射影がずれるので、
  頭上バー・ツールチップ位置の実機確認まで含める。
- `feature/ui-mouse-cards` のマージ完了後、**新しい worktree `feature/board-layout-rework`** で作業する。
- ソース UTF-8 (BOM付き)。`Game/Assets/modelData/*.dds` の phantom modified は commit/discard しない。
- フェーズ引き継ぎは `docs/tasks/board-layout-rework/` の Markdown で自己完結（intent.md → plan.md → 実装 → レビュー）。
- **plan.md 作成時、B（戦闘時の2盤面接続モデル）と座標系設計は、実装細部の裁量を超える設計判断。
  案を固めたうえで、着手前に game-53（マネージャー）のレビューを必ず挟む。**
