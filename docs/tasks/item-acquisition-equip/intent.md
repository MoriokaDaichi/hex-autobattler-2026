# 要件定義: プレイヤー向けアイテム取得・装備導線

- Notionタスク: 「プレイヤー向けアイテム取得・装備導線」(期限 2026-09-16 / ジャンル: アイテム / タスク: 実装)
- 担当: 実装用セッション / 依頼元: マネージャー

## 背景・現状

- `ItemSystem::GiveItem()` は「ユニットへのアイテム付与 + 素材2つの自動合成」を完全実装済みだが、
  呼び出し元は `EnemyFactory` のみで、**プレイヤーがアイテムを入手・装備する手段が存在しない**。
- アイテムのマスターデータ(`ItemDatabase.h`)は完備。素材6種 + 完成品21種、素材の全組み合わせ21通りの
  レシピも定義済み。`GetAllItemDefs()` / `FindItemDefByName()` / `FindRecipe()` が利用可能。
- `UnitInstance::items`(装備済み欄、最大 `ItemSystem::kMaxItemSlots` = 3)はあるが、その手前の
  「未装備アイテムを保持しておく仕組み(インベントリ)」が `Player` に一切ない。
- 入力フォーカスは `CursorSelectionSystem` の `enum class InputFocus { Shop, Bench, Board }` で切り替える設計。
  ショップ/ベンチのような一覧選択と盤面のヘックス選択を共通の語彙で扱っている。

## 目的

準備フェーズで、プレイヤーが入手済みアイテムを bench / board のユニットへ装備できる一連の導線を作る。
装備処理自体は `ItemSystem::GiveItem()` を呼ぶだけで済む(自動合成込み)。

## 要求仕様

1. アイテム入手手段: **PvEラウンドの勝利報酬**方式。ラウンド勝利ごとに素材アイテム1つを入手する
   (ユーザー確認済みの決定事項)。
2. 未装備アイテムの保持先を `Player` に追加する。
3. `InputFocus` にアイテム一覧用のフォーカスを追加し、既存の Shop / Bench と同じ一覧選択の要領で
   対象アイテムを選べるようにする。
4. アイテムを選んだ状態から bench / board のユニットを選んで装備を確定する操作フロー
   (ボタン割り当ては既存パターン踏襲)。確定時に `ItemSystem::GiveItem()` を呼ぶ。
5. 未装備アイテム一覧を表示する新規UI。画面はかなり埋まっている(左上FPS / 左BENCH一覧 /
   右上GOLD・LV・ROUND・連敗 / 下部SHOP)ため、既存UIと重ならない配置にする。

## 既知の制約(FontEngine)

- pivot による中央揃えは機能しない。`kTopLeftPivot` 前提で開始X座標を手動調整する。
- `color.w` による alpha フェードは機能しない。点滅等は描画自体のON/OFF切替で行う。
- ソースファイルは UTF-8 (BOM付き) で保存する(BOM無しだとCP932環境でパースが壊れる)。

## 受け入れ条件

- ビルドが通る(Debug/x64、VS 2026 の v145 ツールセット)。
- 実機で「ラウンド勝利 → アイテム入手 → bench/board のユニットに装備 → 戦闘開始時のステータスに反映」
  の一連の流れが確認できる。
- 既存UI(FPS / BENCH / GOLD・LV / ROUND・連敗 / SHOP)と表示が重ならない。
