# 要件定義: 盤面ユニット配置を自陣(q0〜2)に制限する

- 依頼元: マネージャー（クオリティ比較調査で発見した実バグの修正）
- 担当: 実装用セッション
- 規模: 小（バグ修正）

## 背景・現状

- 盤面は axial 座標で q:0〜8, r:0〜2。設計上の区分けは **q:0〜2=自陣 / q:3〜5=中立 / q:6〜8=敵陣**
  （`Game/HexGridRenderer.h` 52行目のコメント、`Game/HexGridRenderer.cpp` `BuildTileFills()` の
  `q <= 2` → 自陣色 / `q >= 6` → 敵陣色 という塗り分けと一致）。
- しかし `Player::PlaceUnitOnBoard(int benchIndex, const HexCoord& targetPos)`
  （`Game/Player.h`）のバリデーションは
  「ベンチ index 範囲」「レベルによる盤面上限」「マス重複」の3点のみで、
  **targetPos が自陣かどうかを検証していない**。
- カーソル移動側 `CursorSelectionSystem::UpdateHexCursor()` と
  `HexGridRenderer::IsValidHex()` も盤面全体（q:0〜8）を有効としているだけ。
- 結果として、プレイヤーは中立地帯・敵陣（q:3〜8）にもユニットを配置できてしまう。

## 目的

プレイヤーのユニット配置先を自陣（q:0〜2）のみに制限する。

## 要求仕様

1. `Player::PlaceUnitOnBoard` に自陣範囲チェックを追加し、範囲外なら `false` を返す。
2. 自陣範囲の値は `kMinQ` 等の既存定数と重複しない形で管理する。
3. 配置が弾かれたことがプレイヤーに分かるようフィードバック表示を出す。
4. カーソル操作側の扱いは UX 上の違和感が無い範囲で実装者判断に委ねる
   （配置自体が弾かれるなら、カーソルが自陣外へ動けること自体は許容）。

## 実装者の判断（本タスクで採用した方針）

- **配置の可否判定（`Player`）を唯一の防御ラインとする。** カーソルは従来どおり盤面全体を
  移動でき、自陣外を指した状態で配置操作をすると `false` + フィードバックで弾く。
  - 理由: 変更範囲が最小で回帰リスクが低い。盤面全体を見渡せるカーソル挙動は
    据え置きでも UX 上の違和感が無い（配置不可マスは操作時に明示される）。
  - ヘックスカーソルの現状の唯一の用途は配置先指定（`Game.cpp` の X ボタン処理）で、
    ここを塞げば実害はない。
- 自陣範囲定数は `HexGridRenderer` に `public` の
  `kAllyZoneMinQ` / `kAllyZoneMaxQ` を新設し、既存の `BuildTileFills()` の
  マジックナンバー（`q <= 2`）もこれを参照する形へ寄せて単一の出所にする。
  `Player.h` からの参照は循環 include（`HexGridRenderer.h` → `GameState.h` → `Player.h`）を
  避けるため行わず、`Player` 側にも同義の `static constexpr` 定数を、
  出所コメント付きで持たせる。

## 受け入れ条件

- ビルドが通る（Debug / x64）。
- 実機で、自陣（q:0〜2）にはユニットを配置でき、中立・敵陣（q:3〜8）を指した状態では
  配置できず、フィードバックが表示される。
- 敵陣の敵ユニット生成（`EnemyFactory`、`Player::PlaceUnitOnBoard` を経由しない）に影響が無い。
