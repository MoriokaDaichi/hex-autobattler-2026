# プレイテスト指摘 即修正バッチ1 — intent

## 背景
2026-10-01、外部のプレイヤーに実際に遊んでもらいフィードバックを得た。そのうち、比較的小さな修正で直せる5件をまとめて対応する。
(残りの指摘はNotionに個別タスクとして登録済み/登録予定)

## 対象と要求仕様

### A. 連勝/連敗HUDの先バレ
- 現状: 戦闘アニメの再生が終わる前に、画面右上の連勝/連敗HUDが更新され、勝敗が先にわかってしまう。
- 推定原因: `CombatEngine::SimulateCombat` は戦闘開始時に即座に結果まで計算し終えるため、その時点で連勝/連敗が更新・表示されている。
- 要求: 連勝/連敗(およびそれに連動する表示。例: ゴールド・ライフ等で同様の先バレがあればそれも)は、戦闘再生が終わってからHUDに反映する。

### B. マウスオーバー時のステータスに補正が反映されない
- 現状: 盤面上のユニットにマウスオーバーして出るステータス表示に、トレイト/アイテム/★の補正が反映されていない。
- 推定原因: `TraitSystem`/`ItemSystem`/`StarLevelSystem` による `bonus*` の再計算が戦闘開始時にしか行われない。
- 要求: 準備フェーズでも、盤面/ベンチ/装備が変化したら補正を再計算し、ホバー表示は補正込みの値(できれば「基礎値+補正」がわかる形)を出す。
- 注意: 各Apply*は `currentHP` を全回復させる副作用がある。準備フェーズでの再計算がゲームロジック(戦闘開始時の状態)を壊さないこと。

### C. 戦闘開始前の敵ユニットの向き
- 現状: 戦闘開始前、相手盤面のユニットが画面奥を向いている。
- 要求: 敵ユニットは手前(プレイヤー側)を向く。戦闘中の向き制御は既存のまま。

### D. 盤面が薄暗い
- 要求: ライト(ディレクショナル/環境光等)を調整し、盤面とユニットがはっきり見える明るさにする。白飛びはさせない。

### E. 戦闘開始ボタンの配置
- 現状: 戦闘開始ボタンが、リロール/経験値購入/ショップロックと同じ大きさで同じ列に並んでいる。
- 要求: 戦闘開始ボタンはショップ操作とは役割が違うため、独立した位置に置き、より大きく目立たせる(例: 画面右下に大きく)。

## 受け入れ条件
- Debug x64でビルドが通る。
- A〜Eそれぞれ、上記の要求を満たす。既存の操作・フェーズ遷移・戦闘再生を壊していない。
