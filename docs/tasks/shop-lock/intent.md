# ショップのロック機能 — 要件定義

## 背景・現状

- 準備フェーズのショップは5枠。`m_currentShop`(`std::vector<const UnitDef*>`、`Game.h`)が中身を保持する。
- 毎ラウンド、準備フェーズに入った時点で `m_currentShop` が空なら `ShopSystem::RollShop` で自動的に再抽選される(`Game.cpp` の `Phase::Preparation` 内、`if (m_currentShop.empty())`)。
- ラウンドを跨ぐたびに中身が変わるのは、Bボタンで戦闘へ進む際に `m_currentShop.clear()` しているため(`Game.cpp` の `enButtonB` ハンドラ)。次の準備フェーズで空→再抽選、という流れ。
- 手動リロールはYボタン(2ゴールド消費)。

## 目的

TFT本家の「ショップロック」を再現する。ロック中は、ラウンドを跨いだ自動リロールが行われず、ロック時点の5枠がそのまま次ラウンドへ持ち越される。手動リロール(Y)は従来どおり可能。

## 要求仕様

1. ロックのON/OFFをトグルするボタン操作を追加する。準備フェーズの `A/B/X/Y/LB1/RB1` は全て使用済みのため、空いている `enButtonStart`(XInput: START / キーボード: Enter)を割り当てる。
2. ロックON中は、Bボタンで戦闘フェーズへ進む際に `m_currentShop` をクリアしない。これにより次の準備フェーズで「空でない」ため自動リロールがスキップされ、同じ5枠が維持される。
3. ロックOFF中は従来どおり(ラウンド跨ぎで再抽選)。
4. 手動リロール(Y)はロック状態に関わらず常に実行可能。ロック状態は手動リロールでは変化させない(リロール後の新しい5枠がそのままロック対象になる)。
5. `ShopUIRenderer` のヘッダー行に、ロック中であることが分かる表示(`[LOCKED]`)と、操作ガイド(`[Start] Lock`)を追加する。
6. 新規プレイ開始・セーブデータロード時はロックOFFで開始する(ロック状態はセーブ対象外)。

## 受け入れ条件

- ロックON → Bで戦闘 → 勝敗後に準備フェーズへ戻る → ショップの5枠がロック前と同一。
- 続けてロックOFF → Bで戦闘 → 準備フェーズへ戻る → ショップが再抽選され中身が変わる。
- ロックON中でもYボタンでの手動リロールができる。
- ヘッダー行にロック状態が反映される(`[LOCKED]` の有無)。
- ビルドが通り(Debug/x64)、上記を実機(OutputDebugStringログ + 画面)で確認できること。

## スコープ外

- ロック状態のセーブ/ロード永続化。
- ロック中に購入して空いた枠の「空き枠」表示(現状 `BuyUnit` は `m_currentShop` を変更しないため枠は減らない。既存挙動を踏襲)。
- マウス/専用UIボタンでのロック操作(ボタン入力のみ)。
