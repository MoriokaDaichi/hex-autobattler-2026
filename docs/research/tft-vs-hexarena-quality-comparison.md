# TFT本家 vs HEX ARENA(本プロジェクト) クオリティ比較・ギャップ分析

調査日: 2026-08-30 / 調査担当: 外部調査用サブエージェント
参照: [`docs/research/TFT.md`](TFT.md)（TFT本家の要素まとめ）とリポジトリ現行実装（`Game/` 配下）の突き合わせ。

> 本プロジェクトは「TFT風の自作ゲーム(HEX ARENA)」であり、TFTの完全再現が目的ではない。本書はクオリティ向上の参考情報として、気づいた差分・改善余地を客観的に整理したもの。「何を実装すべきか」の断定はしない。

## 0. 全体像の前提差（先に押さえておくと以降が読みやすい）

## 1. UI描画エンジンの制約（すべてのUI項目の土台）

### 現状
- 全2D UIは `IRenderer::OnRender2D` 内で `Font::Draw()` を呼ぶだけ（[`ShopUIRenderer.cpp:143`](../../Game/ShopUIRenderer.cpp#L143) ほか各Renderer）。
- コード中コメントで繰り返し明言されている既知の制約:
  - アルファブレンドが効かない → 半透明の暗幕・フェードができず、`ResultUIRenderer` は「`#` を敷き詰めた不透明ブロック」で暗幕を代用（[`ResultUIRenderer.cpp:56`](../../Game/ResultUIRenderer.cpp#L56)）。
  - `MeasureString` 相当が無い → `pivot` は生ピクセルオフセットで、真の中央揃え・右揃えができない。開始X座標を実機で手動調整している（[`RoundRecordUIRenderer.cpp:11`](../../Game/RoundRecordUIRenderer.cpp#L11)、[`TitleUIRenderer.cpp:9`](../../Game/TitleUIRenderer.cpp#L9)）。
  - スプライトフォントに矩形・ブロック罫線グリフが無い（描くと例外でクラッシュ）→ HPバー・XPバーは `[####------]` のASCII表現（[`BoardUIRenderer.cpp:13`](../../Game/BoardUIRenderer.cpp#L13)、[`PlayerStatusUIRenderer.cpp:21`](../../Game/PlayerStatusUIRenderer.cpp#L21)）。
  - 点滅は「一定間隔で `Draw` 自体をスキップ」して表現（[`TitleUIRenderer.cpp:29`](../../Game/TitleUIRenderer.cpp#L29)）。
- アイコン素材（コストティア枠、トレイトアイコン、ユニットポートレート、アイテムアイコン）を一切使っていない。`ShopUIRenderer.h:17` に「枠・アイコンの作り込みはスコープ外」と明記。

### TFT本家との差分
- TFTのUIは、カード枠・コスト色帯・トレイトアイコン・ユニット絵・HP/マナの実バー・アルファ演出・整列レイアウトが前提。本プロジェクトは「色付きテキスト行」だけで同じ情報を表現しており、情報密度・視認性・"それらしさ" で大きな差がある。
- 特にHP/XP/ゲージ類が全てモノスペースのASCIIバーなので、遠目・戦闘中の可読性が本家のバー表現に比べて弱い。

### 改善余地（優先度感）
- **高**: 単色矩形が1枚描けるだけで表現力が跳ね上がる（HPバー、カード枠、暗幕、トレイトパネル背景）。「1x1白テクスチャのSprite」を1枚追加してスケール描画するだけでも、罫線グリフ問題・アルファ問題・整列問題の多くが緩和される。UI全体の底上げになる基盤investmentなので最優先候補。
- **中**: `Font` に文字列幅計測を1つ足せば中央/右揃えが可能になり、全Rendererの「手動X調整」コメントが消える。
- **低〜中**: コストティア色（[`ShopUIRenderer.cpp:32` CostTierColor](../../Game/ShopUIRenderer.cpp#L32)）は既にTFTのグレー/緑/青/紫/金に寄せてある。方向性は合っているので、枠が描けるようになったら流用できる。

## 2. ショップUI

### 現状（[`ShopUIRenderer`](../../Game/ShopUIRenderer.cpp) / [`ShopSystem`](../../Game/ShopSystem.h) / [`Game.cpp:135` 以降](../../Game/Game.cpp#L135)）
- 画面下部に5枠を横並び。各枠は2行テキスト（1行目=ユニット名、2行目=`C{cost} HP{n} AT{n} {トレイト}`）。
- コスト帯色は反映。カーソル選択枠は `> ` プレフィックス＋1.08倍拡大＋非選択枠を暗くする。
- ヘッダー行に `SHOP Gold n Lv n (XP x/y) [Y] Reroll -2G [RB1] BuyXP -4G`。
- 操作フィードバック行（購入成功/ゴールド不足/リロール等）を、直近3秒は明るく、その後は薄く常時1行残す（[`ShopUIRenderer.cpp:126`](../../Game/ShopUIRenderer.cpp#L126)）。丁寧。
- 抽選: レベル別コスト帯オッズテーブル（[`ShopSystem.h:64`](../../Game/ShopSystem.h#L64)）。リロール2ゴールド。

### TFT本家との差分
- **カード形式でない**: 本家はユニット絵・コスト帯・トレイトアイコン付きカード5枚。こちらは文字。
- **ロック機能なし**: 本家のショップ「ロック」（次ラウンドまで再抽選を防ぐ）が無い。
- **プール枯渇なし**: `RollShop` は各コスト帯から一様ランダムに選ぶだけ（[`ShopSystem.h:50`](../../Game/ShopSystem.h#L50)）。本家の「バッグ制（1コスト各30枚…誰かが買うと減る）」が無いため、同じユニットが何体でも無限に出うる。★3集めの難度・"コントラクト"の駆け引きが発生しない。
- **オッズが9レベルまで**: 本プロジェクトは最大Lv9（[`LevelSystem.h:12`](../../Game/LevelSystem.h#L12)）。本家はLv10–11まであり4/5コスト比率がさらに伸びる。数値も微妙に違う（例: 本家Lv7の3コスト43%に対し本プロジェクトは35%）。
- **ショップ確率表示なし**: 本家はショップ上にレベル別オッズ％を常時表示。
- **購入方法**: 本家はドラッグ or クリック。こちらはカーソル＋Aボタン。

### 改善余地（優先度感）
- **中**: ロック機能は実装が軽く（`bool m_shopLocked` を持って `m_currentShop.empty()` 判定と併用）、TFT体験の要なので費用対効果が高い。
- **中**: プールのバッグ制。★3の達成感・敵とのユニット取り合いという中核ループに直結するが、敵が固定編成のため「取り合い」相手がおらず、恩恵は本家より小さい。入れるなら「自分の消費で減る」だけの簡易版で十分。
- **低**: オッズ表示。枠/整列が描けるようになってから。
- **低**: Lv10対応。現状の10ラウンド設計だとLv9で十分機能する。

## 3. 盤面まわりのUI（HPバー・ベンチ一覧）

### 現状（[`BoardUIRenderer`](../../Game/BoardUIRenderer.cpp)）
- 準備フェーズ: 画面左に `BENCH (n)` と縦並びのベンチ一覧（名前＋`*2` の星表記）。
- 戦闘フェーズ: 各ユニット頭上にHPバー（`[####------] hp/maxHP (+shield)`）＋名前＋星。ワールド座標をVP行列でUI空間に射影（[`BoardUIRenderer.cpp:62` WorldToUI](../../Game/BoardUIRenderer.cpp#L62)）。HP割合で緑/黄/赤に色分け。撃破済みはバー非表示。

### TFT本家との差分
- **ベンチが3D盤面上に無い**: 本家は盤面手前に9スロットの実ベンチがあり、そこにユニット模型が乗る。こちらはベンチ＝画面左のテキストリスト、3D空間には盤面配置済みユニットしか出ない（[`UnitModelDisplay.cpp:25`](../../Game/UnitModelDisplay.cpp#L25) は `player.board` のみ）。
- **HP/マナバーの質**: 本家は実バー＋マナ（青）バーが常時。こちらはASCIIのHPバーのみで**マナ/スキルゲージのバーが無い**（スキル発動タイミングが見えない）。スキルゲージは内部的には `normalAttackCount + receivedAttackCount` vs `skillThreshold`（[`CombatEngine.h:177`](../../Game/CombatEngine.h#L177)）。
- **敵のHPバー**: 実装済み（`isEnemy` で赤系）。ここは方向性OK。
- **ベンチ枠数の上限が未強制**: `player.bench` は上限チェックが無く、`BuyUnit` で無制限に積める（[`Player.h:52`](../../Game/Player.h#L52)）。本家は9枠上限で溢れると買えない/自動売却。

### 改善余地（優先度感）
- **中**: スキルゲージバー（HPバーの下にもう1本）。戦闘の「必殺技くる！」の見え方が本家に近づく。`CombatPlayback` に `displayGauge` を足し、`CombatEvent` にゲージ変化を積めば再生可能（イベント種別追加が必要）。
- **低〜中**: ベンチ枠上限（9）＋溢れ処理。ゲームバランスというより体験の一貫性。
- **低**: ベンチを3D盤面手前に模型で並べる。工数大（`UnitModelDisplay` をベンチにも対応させる）、見た目インパクトは大きい。

## 4. ゴールド / レベル / XP 表示

### 現状（[`PlayerStatusUIRenderer`](../../Game/PlayerStatusUIRenderer.cpp)）
- 画面右上に2行常時表示: `GOLD n`（金色）と `LV n [####------] xp/next`（最大時 `LV n (MAX)`）。
- 全フェーズで表示（`Game::Render()` のフェーズ分岐外で `Draw`）。

### TFT本家との差分
- **利子の可視化なし**: 本家はゴールド表示の近くに利子アイコン（10ゴールドごとの丸）を出し、次の利子まであといくらかが直感的に分かる。こちらは数値のみ。
- **「XP購入」ボタンが無い**: 本家はレベル欄自体がクリック可能なXP購入ボタン＋現在Lv/次Lvまでのバー。こちらはショップヘッダーの `[RB1] BuyXP -4G` という文字ガイドのみ。
- **配置可能数の表示**: 本家はレベル＝盤面上限をアイコンで明示。こちらは配置失敗時のフィードバック文（`盤面 n/上限`、[`Game.cpp:317`](../../Game/Game.cpp#L317)）でしか分からない。
- 位置・色（コストティア5＝金と同系）はセンス良くまとまっている。

### 改善余地（優先度感）
- **中**: 「盤面 使用/上限」を常時1行足す（`GetMaxBoardSize()` を出すだけ）。配置ミスが減り、レベルを上げる動機付けにもなる。
- **低〜中**: 利子ドット表現（`●●●○○` を金色で）。矩形不要、既存のASCII手法で今すぐできる。
- **低**: XP購入を独立したHUDボタン風表示に（枠が描けるようになってから）。

## 5. ラウンド数・戦績表示

### 現状（[`RoundRecordUIRenderer`](../../Game/RoundRecordUIRenderer.cpp)）
- 画面右上（GOLD/LVの下段）に `ROUND n / 10` / `残り n ラウンド` / `連敗 n / 3`。連敗数で通常/黄/赤に色分け。

### TFT本家との差分
- 本家に「ラウンドn/10」「連敗n/3」という概念そのものが無い（本家は無限ステージ＋8人HP）。**この項目は本プロジェクト独自設計**なので"差分"というより設計の別物。
- 本家の対応物は「ステージ-ラウンド表記（2-1, 2-2…）＋次がPvEかキャロセルかのラウンドプレビュー帯」。本プロジェクトにラウンド種別（PvE/キャロセル/対人）の区別が無いので、プレビュー帯に相当するものも無い。
- 連勝/連敗ストリークは `EconomySystem` が内部で持つ（[`Player.h:19`](../../Game/Player.h#L19)）が、UIに出ていない（本家はストリーク炎アイコンで表示）。

### 改善余地（優先度感）
- **中**: 連勝/連敗ストリーク数の表示。既に `player.winStreak / lossStreak` があるので出すだけ。収入ボーナスの根拠が見えてゴールド計画が立てやすくなる。
- **低**: 次ラウンドの敵編成プレビュー（`EnemyStage::label` が既にあり "Round7: Paladin Vanguard" 等）。偵察の代替になる。

## 6. アイテム（システム＋UI）

### 現状（[`ItemSystem`](../../Game/ItemSystem.h) / [`ItemDatabase`](../../Game/ItemDatabase.h) / [`ItemInventoryUIRenderer`](../../Game/ItemInventoryUIRenderer.cpp)）
- 素材6種（Power/Vital/Guard/Iron/Wisdom/Swift = AT/HP/HP%/物防/AP/AS%）。
- 完成品21種＝6素材の全ペア（同素材ペア含む）に決定論レシピ（[`ItemDatabase.h:198`](../../Game/ItemDatabase.h#L198)）。1体3スロット、素材を重ねると自動合成（[`ItemSystem.h:20` GiveItem](../../Game/ItemSystem.h#L20)）。
- 効果は `StatEffect`（flat/percent の加算）のみ。毎ラウンド `ApplyItemBonuses` で `bonus*` を再計算（[`ItemSystem.h:61`](../../Game/ItemSystem.h#L61)）。
- 入手手段: ラウンド勝利報酬で素材1個（[`Game.cpp:499` PickRandomComponent](../../Game/Game.cpp#L499)）。
- UI: 画面右側に未装備アイテム一覧（名前＋`AT+10 HP+20%` の短縮効果テキスト）。カーソルで選び[A]で"手に持つ"→ベンチ/盤面のユニットを選び[A]で装備（[`Game.cpp:187`](../../Game/Game.cpp#L187)）。

### TFT本家との差分
- **素材6種 vs 9種**: 本家は BF Sword / Recurve Bow / Needlessly Large Rod / Tear / Chain Vest / Negatron / Giant's Belt / Sparring Gloves / Spatula。特に **Tear（マナ）と Sparring Gloves（クリティカル/回避）に相当する素材が無い**。攻撃速度素材（Swift）は本家の Recurve Bow に対応。
- **完成品21種 vs 45種**。
- **Spatula/エンブレムが無い**: ユニットに特性タグを追加する仕組みが無い。本プロジェクトはトレイトが少数固定なので影響は限定的だが、構成の自由度は本家より低い。
- **効果がステータス加算のみ**: 本家の完成品はパッシブ効果（Burn/Wound/Shred/Sunder付与、条件付き発動、オーラ、回復、リゾルブ等）が主役。本プロジェクトの完成品は「素材の合算より少し強い数値」（[`ItemDatabase.h:64` コメント](../../Game/ItemDatabase.h#L64)）に留まり、質的な差別化が弱い。`SkillThresholdFlat`（必殺技を早める）だけは効果らしい効果だが、レシピ側で使われていない。
- **入手経路が単一**: 本家はPvE報酬（複数個ドロップ）＋キャロセル（素材付きユニット）＋アイテムオーブ。本プロジェクトは「勝ったら素材1個」のみで、負けると増えない＝負けてる側がさらに苦しい。
- **装備UIがドラッグでない**: 本家は素材アイコンをユニットにドラッグ。こちらは"手に持つ"2ステップのカーソル操作。機能はするが直感性で差。
- **アイテムの見た目**: アイコン無し、完成予測（この2素材で何ができるか）の表示無し。本家はホバーでレシピツリーが見える。

### 改善余地（優先度感）
- **中**: 完成品にパッシブ効果を1〜2個入れる（例: 「攻撃時に対象へ数ラウンド継続の火傷」→ `CombatEvent` にDoT種別追加）。今は `StatEffect` 加算だけなので、"アイテムでビルドが変わる" 感を出すなら効果の種類を増やすのが本丸。
- **中**: 未使用の `SkillThresholdFlat` / マナ相当ステータスをレシピに組み込む（本家Tearの枠）。
- **低〜中**: 「持っている素材2個で作れる完成品」のプレビュー表示。
- **低**: 素材を9種に拡張、Spatula追加。トレイト設計を広げるなら合わせて。

## 7. 特性（トレイト / シナジー）システム — ★UIが存在しない点が最大の指摘対象

### 現状（[`TraitSystem`](../../Game/TraitSystem.h) / [`TraitDatabase`](../../Game/TraitDatabase.h) / [`TraitDef`](../../Game/TraitDef.h)）
- 8トレイト: 出自系 Monster/Human/Hero、役割系 Warrior/Mage/Guardian/Assassin/Ranger（[`TraitType.h`](../../Game/TraitType.h)）。
- 各トレイトは2段階（`TraitTier`）: ほとんどが 2体 / 4体（Heroのみ 1体 / 2体）。効果は `StatEffect` の加算（AT%、HP%、物防/魔防 flat、`SkillThresholdFlat` -1/-2 等）。
- 毎戦闘開始時に盤面のタグ数を集計 → 満たす最高段階の効果を該当ユニットへ適用 → HP全回復（[`TraitSystem.h:19`](../../Game/TraitSystem.h#L19)）。持続バフの蓄積は無い。
- **表示は `OutputDebugString` のみ**（[`TraitSystem.h:128` LogActiveTraits](../../Game/TraitSystem.h#L128)）。画面上にトレイトパネルが無い。ショップのカードに各ユニットのトレイト名が最大2個出るだけ（[`ShopUIRenderer.cpp:96`](../../Game/ShopUIRenderer.cpp#L96)）。

### TFT本家との差分
- **左側トレイトパネルが丸ごと未実装**。本家は画面左に「発動中トレイトを上・ハイライト、未発動を下・ディム、各行に現在人数 / 次の閾値、色分け（ブロンズ/シルバー/ゴールド/プリズム）」を常時表示。これがオートバトラーの中核HUDで、**プレイヤーが構成を組み立てる際の主要な意思決定情報**。現状これがゼロなので、プレイヤーは自分が何のシナジーを何体揃えているかを画面から把握できない（デバッガ出力を読むしかない）。
- **段階が2つだけ**: 本家は 2/4/6（さらに 3/5/7、ユニークトレイトは1）と3段階以上が普通。伸びしろ・"あと1体"の緊張感が本家より浅い。
- **効果が数値バフのみ**: 本家トレイトの目玉である「特殊メカニクス型」（例: 一定時間後に最低HP敵を処刑、召喚、フィールド効果、変身、リソース生成）が無い。`TraitSystem` は `StatEffect` しか適用できない構造。
- **出自×役割の2軸**はある（1ユニットが複数タグ、例 `ChimeraLord` = Monster/Human/Hero/Warrior）。ここは本家の設計思想と合致。
- ユニット14種に対しトレイト8種なので、1トレイトあたりの母数が少なく4体揃えるのが窮屈（本家は1トレイトに5〜10体）。

### 改善余地（優先度感）
- **最高**: **トレイトパネルUIの新規実装**。Notionの残タスクにも挙がっている通り、ここが体験上いちばん大きな欠落。まずは「発動中/未発動の一覧＋`現在数/次閾値`」のテキスト版だけでも価値が高い（`TraitDatabase` と `player.board` から集計するだけで、既存の `LogActiveTraits` のロジックがほぼ流用できる）。左側は `BoardUIRenderer` のベンチ一覧（`kBenchX = -910`）と競合するので配置調整は要検討。
- **中**: トレイト段階を2→3に（2/4/6）。`TraitTier` は可変長なので `TraitDatabase::Init` にもう1段足すだけ。
- **中〜高**: 「特殊メカニクス型」トレイトを1つでも。`TraitSystem` に `StatEffect` 以外のフック（戦闘開始時コールバック等）を足す設計変更が要る。
- **低**: ユニット追加でトレイトあたりの母数を増やす（モデルパイプラインと連動）。

## 8. 戦闘表現

### 現状（[`CombatEngine`](../../Game/CombatEngine.h) / [`CombatPlayback`](../../Game/CombatPlayback.cpp) / [`CombatLogPrinter`](../../Game/CombatLogPrinter.h)）
- `SimulateCombat` が1フレームで戦闘を瞬時解決し `CombatEvent` 列を出力（イベント駆動、`nextActionTime` 内部時計、ウェーブ単位交互行動）。
- `CombatPlayback` がそのイベント列を約6秒（速度1.0〜5.0倍で尺調整）かけて時系列再生。**再生するのはHPバー/シールドの数値変化のみ**。
- **位置アニメーションはしない**（[`CombatPlayback.h:17` 明記](../../Game/CombatPlayback.h#L17)）: HPバーは戦闘開始時の `homePosition` に固定。
- 3Dモデル: `UnitModelDisplay` は `player.board` のユニットを `homePosition` に静止表示するのみ。**敵モデルは3D表示されない**。攻撃/移動/必殺技/死亡のアニメクリップはロードされる（[`UnitModelDisplay.cpp:94`](../../Game/UnitModelDisplay.cpp#L94)）が、戦闘中に再生されていない（`SetTRS` のみ、クリップ切り替え無し）。
- 必殺技のエフェクト・ヒットエフェクト・投射物なし。`CombatLogPrinter` がテキストで詳細を出す。

### TFT本家との差分
- 本家の戦闘は「模型が実際に移動し、通常攻撃モーション・必殺技の固有エフェクト・投射物・被弾リアクション・死亡演出」がフルに動く、いわば見せ場。本プロジェクトの戦闘は**盤面が静止したままHPの数字とASCIIバーだけが変動する**ため、"戦っている絵" にはなっていない。CLAUDE.md でも 3D移動アニメは別タスク・スコープ外と整理されている。
- 一方、シミュレーションと表示を分離した設計（`CombatEvent` 列）は拡張しやすく、演出を後付けする土台としては良好。
- 相打ち（両全滅）を敗北扱い（[`Game.cpp:465`](../../Game/Game.cpp#L465)）、経路探索は貪欲な隣接移動のみ（[`CombatEngine.h:212` MoveTowards](../../Game/CombatEngine.h#L212)）——ここはゲーム性として本家より簡略。

### 改善余地（優先度感）
- **高（ただし工数大）**: 戦闘中のユニット3D位置を `CombatEvent::Move` に沿って補間表示＋敵モデルも出す。「戦っている絵」の有無はクオリティ体感の最大要因。イベント列は既にあるので、`UnitModelDisplay` を「playback参照モード」に拡張する形。
- **中**: 攻撃/必殺技/死亡アニメクリップの再生（クリップはロード済み）。位置移動より軽く、効果は大きい。
- **中**: 必殺技の簡易エフェクト（Effekseer がミドルウェアに入っている）。
- **低**: HP数値のダメージポップアップ（既存のASCII手法で可能）。

## 9. 経済（ゴールド）システム

### 現状（[`EconomySystem`](../../Game/EconomySystem.h)）
- 基本収入 +5固定 / 利子 = `gold/10`、上限+5 / 連勝・連敗ボーナス = 2連 +1、3–4連 +2、5連以上 +3。
- 初期ゴールド10（[`Game.cpp:98`](../../Game/Game.cpp#L98)）。売却額 = `cost × 3^(star-1)`（[`Player.h:104`](../../Game/Player.h#L104)）。

### TFT本家との差分
- **序盤の収入ランプが無い**: 本家は 2-1 までが 2/2/3/4 ゴールドと絞られ、2-2 から5固定。本プロジェクトは最初から+5。
- **PvP勝利 +1 が無い**: 本家は対人勝利で追加+1。本プロジェクトの `GrantRoundIncome` に勝利分の加算は無く、勝っても負けても基本+5＋利子＋ストリーク。
- **ストリークボーナスが本家より優しい/早い**: 本家は 3–4連=+1 / 5連=+2 / 6連以上=+3。本プロジェクトは 2連で早くも+1、5連で+3に到達（[`EconomySystem.h:71` GetStreakBonus](../../Game/EconomySystem.h#L71)）。
- 利子上限50ゴールド、`/10` 刻みは本家と一致。売却は本家準拠（★2=3倍, ★3=9倍、一部本家は3コスト★3で-1の例外あり）。

### 改善余地（優先度感）
- **低〜中**: 数値を本家に寄せるかは "自作ゲームの調整" の範疇。10ラウンド固定・敵固定という短距離設計なので、序盤ランプ廃止やストリーク優遇は「早くパワースパイクさせる」意図として妥当とも読める。差分として認識しておけば十分。
- **低**: PvP勝利+1相当を入れるなら、勝ち continued 報酬（現状は勝利時に素材1個＝[`Game.cpp:499`](../../Game/Game.cpp#L499)）で既にある程度カバーされている。

## 10. レベル / XP システム

### 現状（[`LevelSystem`](../../Game/LevelSystem.h)）
- 最大Lv9。XP購入 4ゴールド→4XP。毎ラウンド自動+2XP。
- 次Lvまでの必要XP: `{2, 2, 6, 10, 20, 36, 48, 72, 0}`（Lv1→2が2、… Lv8→9が72）。
- Lv = 盤面配置上限（[`Player.h:26`](../../Game/Player.h#L26)）。

### TFT本家との差分
- 本家の必要XP: 2 / 2 / 6 / 10 / 20 / 36 / 56 / 80 / 84 / 100（Lv10まで）。**Lv7→8以降が本プロジェクトの方が軽い**（56→48、80→72）。到達が早い。
- 本家は最大Lv10（一部モードLv11）。本プロジェクトはLv9。
- 「4ゴールドで4XP」「毎ラウンド2XP」は本家と一致。
- 本家の序盤XPランプ（ステージ1は自動XPが渋い）は本プロジェクトでは考慮なし（常に+2）。

### 改善余地（優先度感）
- **低**: 10ラウンド設計なら Lv9 上限・やや軽いXPカーブは整合的。本家準拠にする必然性は薄い。差分認識で足りる。

## 11. 盤面レイアウト・カメラ・配置ルール

### 現状
- 盤面 q:0–8 × r:0–2（27ヘックス、pointy-top、`kHexSize=50`）。自陣 q0–2 / 中立 q3–5 / 敵陣 q6–8 をゾーン色分け（[`HexGridRenderer.cpp:219` BuildTileFills](../../Game/HexGridRenderer.cpp#L219)）。
- カメラは `Start()` で固定（pos `{0, 900, -650}`、target 原点）。回転・ズーム操作なし（[`Game.cpp:48`](../../Game/Game.cpp#L48)）。
- カーソルはマウスピッキング（レイ×y=0平面）＋矢印/D-pad＋Tabでフォーカス巡回（Shop→Bench→Items→Board）（[`CursorSelectionSystem.cpp`](../../Game/CursorSelectionSystem.cpp)）。
- 配置は `PlaceUnitOnBoard`（[`Player.h:65`](../../Game/Player.h#L65)）: 盤面上限と重複マスだけチェック。**自陣ゾーン（q0–2）に限定していない** → カーソルが届く範囲（q0–8）ならどこでも置ける。

### TFT本家との差分
- **配置可能エリアの制限が無い**: 本家は自分の半面（手前2列＝ヘックス盤で自陣側）にしか置けない。本プロジェクトは中立・敵陣にも置けてしまう（`BuildTileFills` はゾーン色を塗るが、配置ロジックはゾーンを見ていない）。仕様意図が「自陣のみ」なら軽微なバグ、意図的なら本家と異なるルール。
- **前衛/後衛の列の概念が浅い**: 奥行きr方向が3行しかなく、本家の4行＋"相手盤面と合体して8行"のような前後の駆け引きの幅が狭い。
- **カメラ操作なし**: 本家は限定的な視点調整が可能。単一固定でも成立はするが、戦闘の見せ場が作りにくい。
- **ドラッグ移動なし**: 盤面上のユニット再配置は「配置」動作のみで、盤面→盤面のドラッグ移動・盤面↔ベンチの入れ替えUIが見当たらない（`PlaceUnitOnBoard` はベンチ→盤面の一方向）。

### 改善余地（優先度感）
- **中**: 配置を自陣ゾーン（q≤2）に制限（`PlaceUnitOnBoard` に1行）。意図と実装を一致させる。
- **中**: 盤面上ユニットの再配置（盤面内移動・ベンチへ戻す）。準備フェーズの手触りに直結。
- **低**: カメラの軽い可動 or 戦闘時の寄り。

## 12. その他（俯瞰）

- **タイトル/リザルト画面**: `TitleUIRenderer`（"HEX ARENA"、2026-08-30正式決定）、`ResultUIRenderer`（ROUND CLEAR! / DEFEAT... / GAME OVER / VICTORY!）は実装済み。点滅・暗幕をASCIIで工夫している。本家のような装飾性は無いが機能は揃っている。
- **サウンド**: 本調査範囲のコードでは戦闘/UI SEの再生箇所を確認できず（エンジンにサウンド機構はあるが `Game/` から未使用の可能性）。本家はUI操作音・戦闘音がフルにある。
- **情報の一貫した居場所**: 現状HUDは「左上=FPS、左=ベンチ、右上=GOLD/LV→ROUND/連敗→ITEMS、下=ショップ＋フィードバック」と、各Rendererのコメントで座標の衝突を手作業で回避している（[`RoundRecordUIRenderer.cpp:24`](../../Game/RoundRecordUIRenderer.cpp#L24) 等）。トレイトパネルを足すと左側がさらに混むため、追加前にHUDレイアウト全体の再設計が要る。
- **ユニット情報の詳細表示なし**: 本家はユニットをホバー/選択するとステータス・スキル説明・トレイト・アイテムのカードが出る。本プロジェクトはショップカードの `HP/AT` と名前のみで、スキル効果・射程・攻撃速度・魔力・防御は画面に一切出ない（`UnitDef` には全部ある）。
